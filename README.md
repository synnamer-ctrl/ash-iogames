# Little Wonder World

An original, illustrated digital toybox for young children. You can tap, drag, build, draw and discover things across four hand-painted worlds. There are no missions, timers, scores or ads: the only goal is to play.

It's a responsive web app (installable as a PWA) built with **TypeScript, Vite, Phaser 3, React, IndexedDB and the Web Audio API**. Every illustration and sound is original and generated by code in this repository.

## Run it

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # type-check + production build into dist/
npm run preview    # serve the production build on http://localhost:4173
```

Tests:

```bash
npm test           # unit tests (Vitest, jsdom, fake-indexeddb)
npm run build && npm run test:e2e   # browser tests (Playwright, desktop + mobile touch)
```

Asset tooling (only needed when changing art):

```bash
npm run assets     # regenerate every SVG in public/assets + src/data/asset-manifest.ts
npm run icons      # rasterise the PWA icons into public/icons
```

## The worlds

| World | What you can do |
| --- | --- |
| **Little Town** | Tap a house to open its door and see who peeks out. Long-press it to switch its lights. The bakery and flower shop pop out treats and flowers. Drag cars, the bus, the bike or the ice-cream van onto the road and they drive. Cars stop at a red light. Tap the traffic light, mailbox, street lamps and hydrant. Pip and Nana wave when tapped and walk when long-pressed. The dog barks and the cat meows or purrs. Tap the sun to turn day into night. |
| **Nature Garden** | Drop a seed packet on a soil patch to plant it. Water it with the watering can or rain from a cloud, and it grows from seed to sprout to bud to bloom (always the same, predictable steps). Tap the sun after rain for a rainbow. Birds fly between trees and perch, butterflies visit flowers, and the bee buzzes around. The frog hops between lily pads and the duck swims. Things splash into the pond. The rabbit eats carrots, the shy hedgehog curls up when something lands nearby, and the shovel digs new soil patches. |
| **Creative Workshop** | Paint freehand with the brush, waxy crayon or eraser, in 11 colours and 4 sizes. Use 6 rubber stamps, or fill the whole paper with the paint bucket. Place, rotate and resize stickers and paper cut-outs (tap a cut-out to change its colour), and give a shape googly eyes. Undo and redo everything, clear the page (with confirmation), and export the artwork as a PNG. Drawing works with mouse, touch and stylus. |
| **Build & Play** | Real rigid-body physics (Matter.js). Stack blocks, roll balls and toy cars down ramps, and drop balls from the chute. Knock over a domino chain, ring the bell, bounce on the spring, tip the seesaw and spin the pinwheel. The starting scene is a ready-made chain reaction. |

Each world has hidden **discoveries** (41 in total). The star jar shows found ones in colour and the rest as mystery silhouettes. Nothing is ever shown upfront.

## Controls

- **Tap**: activate. **Drag**: move (objects lift, cast a shadow and settle with a little bounce). **Long-press**: a second action (lights, walk, flip, rotate).
- One finger on empty space pans; two fingers (or the mouse wheel) zoom.
- Corner buttons: home, undo, redo, discoveries, sound on/off, settings, start over (asks first), *My creations*, and the toy box (the object library).
- Keyboard: every menu and button can be reached with Tab and Enter. Esc closes dialogs. Ctrl/⌘+Z undoes, and Ctrl/⌘+Shift+Z or Ctrl+Y redoes.

## Saving

- **Autosave**: each world's current scene is written to IndexedDB about a second after every change and when you leave. Refreshing the page or switching worlds never loses work. If the browser refuses storage (private mode or a full disk), the game says so and asks before you leave a world with unsaved changes.
- **My creations**: save any number of named scenes per world with a thumbnail. You can open, rename, save over or delete them, and deleting asks first. A save only reports success after the IndexedDB transaction has committed.
- **Format**: a versioned, validated JSON snapshot (`src/types/game.ts`: `SceneSnapshot`). Each object stores `id, type, x, y, rotation, scale, depth, state`. Workshop drawings are stored as vector strokes and replay exactly. Loaded data is validated: unknown types are dropped, numbers are clamped, and stroke and point counts are capped.
- Settings (volumes, calm motion) are small per-device preferences kept in `localStorage`. No image blobs ever go into `localStorage`.

## Art bible

All 187 illustrations are hand-authored SVG, written in code (`scripts/art/*.mjs`) with one shared toolkit (`scripts/art/lib.mjs`). That keeps the style consistent:

- **Shapes**: jittered, smoothed polygons and blobs, so nothing is a perfect geometric primitive. Silhouettes are rounded and friendly.
- **Line**: deep ink `#38454A` at 3.4 px (details 2.4 px, fine 1.6 px), with a faint offset second line for a sketchy feel.
- **Paint**: a flat base colour, a darker shade crescent toward the lower right, a soft highlight to the upper left, and colored-pencil strokes clipped inside every shape. Backgrounds also get a paper-grain filter.
- **Palette**: cream `#FFF7E8`, sky `#9EDDF5`, leaf `#9BCF8A`, sunshine `#FFD66B`, coral `#F58F83`, lavender `#C5B5F0` and ink `#38454A`, extended with deeper and lighter variants (`P` in `lib.mjs`). Shadows darken toward a warm ink rather than black.
- **Scale**: assets are authored 1:1 with the 1600×1000 world, so line weights match everywhere. Backgrounds include a 200/125 px painted bleed.
- **Faces**: two dark oval eyes with a highlight, rosy cheeks and a small smile, shared by every character.

`node scripts/preview-assets.mjs out.png [filter]` renders a contact sheet of the art.

## Architecture

```
src/
  app/            App shell (React), settings
  components/     WorldSelector, GameToolbar, ObjectLibrary, SaveDialog, SettingsPanel,
                  DiscoveryPanel, ConfirmDialog, WorkshopTray, Modal, IconButton, ObjectThumb
  data/           objects.ts (object definitions), combinations.ts (data-driven combos),
                  discoveries.ts, layouts.ts (starting scenes), worlds.ts, assets.ts,
                  asset-manifest.ts (generated), world-layout.json (shared with the art scripts)
  game/
    Game.ts       GameHost: the single Phaser.Game plus the GameController API used by React
    GameBridge.ts Typed event emitter between the game and the UI
    scenes/       WorldScene (shared base) + Town, Garden, Workshop, Build
    objects/      InteractiveObject (the reusable object model)
    systems/      InteractionSystem, CombinationSystem, AnimationSystem, EffectsSystem,
                  CameraRig, AudioSystem, SaveSystem, DiscoveryStore, UndoStack
    drawing/      Painter (vector stroke rendering for the workshop and PNG export)
    logic/        Pure gameplay rules (plant growth)
  utils/          coordinates, geometry, validation, rng
scripts/art/      The illustration generator (art bible in code)
tests/unit, tests/e2e
```

- **Object model**: `ObjectDef` (data) describes the art, parts, tags, interaction types, layer, hit area, idle animation, limits and default state. `InteractiveObject` is the runtime object (`id, objType, assetKey, position, rotation, scale, depth, interactionTypes, animationState, persistentState`). Its behaviour comes from small per-type modules (`TypeBehavior`: `tap`, `longPress`, `dragStart/Move`, `drop`, `nearby`, `update`, `apply`).
- **Interaction**: `InteractionSystem` gives each pointer (mouse, touch or pen) one gesture captured on press. Movement past a small threshold cancels the tap, so a tap never drags, and a drag only moves the object it started on. Gestures on empty space pan or pinch-zoom. When the window loses focus, any held object is dropped.
- **Combinations**: rules in `data/combinations.ts` match an actor and a target by type, tag or state (`drop`, `hover` or physics `contact`), or a named zone (road, pond, meadow, paper). Each rule names an action, an optional sound and effect, and the discovery it unlocks. To add a combination, you add one rule and one action.
- **Coordinates**: objects live in world coordinates. `CameraRig` only changes zoom and centre on resize, so rotating a phone never moves anything.
- **Performance**: textures load per world and the previous world's are released. Particles are pooled and capped (70 maximum), idle animations exist on only a few objects, physics bodies sleep and are capped (70), and the render loop sleeps on the home screen. With *Calm motion* on, movement is replaced by soft fades.
- **Audio**: all sound effects and the gentle generative music-box score are synthesised with the Web Audio API. Nothing plays until the first user gesture. Sound effects and music have separate switches and volumes.

## Accessibility & child-friendly design

Large touch targets (at least 46 px, most 54 to 76 px), visible press feedback, no flashing, no timers, no failure states, and almost no reading needed. Labels exist for screen readers and grown-ups. Reduced motion follows the OS setting and can be toggled. Dialogs trap focus and close with Esc. There are no ads, accounts, tracking or external links.

## Known limitations

- The bundled Phaser engine is about 340 KB gzipped; the first visit loads it once (then it is cached offline by the service worker).
- Physics, drawing and audio were tested in Chromium (desktop and mobile emulation, including real touch events). Safari and Firefox were not run here. The code uses only standard APIs, but those browsers have not been verified.
- The paint bucket fills the whole paper rather than flood-filling an enclosed area.
- Workshop drawings are capped at about 250,000 points per page to keep memory bounded. The game says when the page is full.
